Trophy Case — Cross-Game Achievements & Celebrations

Status:in-progress
Date:2026-07-12
Branch:feat/trophy-case
Type:plan

Goal

One shared achievements engine that lifts every game and app at once: universal, auto-derived achievements (first play, play-count tiers, personal bests, streaks, cross-game explorer tiers) unlocked from the progress data all 34 modules already keep, celebrated with a confetti toast, and displayed in a trophy case on the profile page. Zero per-island edits: detection rides the one hook every synced module already mounts (useAuthSync).

Context: design/FRAMEWORK_ROADMAP.md fun-mechanics items; CLAUDE.md "Make it FUN first"; cookie-clicker's island-local achievements stay as-is and coexist. Works for guests AND signed-in kids; syncs across devices for the signed-in ones.

Design

Engine (pure, shared): shared/lib/achievements/ holds typed definitions and a pure evaluator. Normalization is alias-based (PLAYS/BEST/STREAK field alias tables scanned against each app's progress blob) — deliberately NOT importing the profile island's gameStatExtractor, because shared code must never depend on an island; aliases also cover future games automatically.

Detection: a new ALWAYS-ON 1s change-poll effect inside useAuthSync (the existing poll is auth-gated, which would exclude guest kids) reports (appId, state) to the store's reportProgress. It skips appId === "achievements" (no feedback loop). Unlocks are idempotent: an id already in the unlocked set never fires again; personal-best fires only on an OBSERVED increase past a persisted per-app watermark (first report just seeds the watermark), while play-count tiers unlock retroactively on first evaluation (a delightful trophy burst for existing progress).

State: Zustand persist store, key achievements-progress (suffix-covered by signOutAndClear). Synced shape: { unlocked: Record<id, unlockedAt>, lastModified } — registered in VALID_APP_IDS and PROGRESS_SCHEMAS (.strict(), boundedRecord + timestampSchema). Watermarks persist locally but are partialized OUT of the synced blob. Celebration queue is session-only (never persisted): reload never re-celebrates.

Surfaces: <AchievementCelebrations /> mounted once in the root layout — confetti toast (CSS only, no new deps), pointer-events-none wrapper so it never eats gameplay taps, queues multiple unlocks, auto-advance + a ≥44px dismiss. Trophy case section on the profile page: unlocked + locked (🔒) grouped per app via gameMetadata.generated, header count, kid-warm empty state. The profile progress list must SKIP the "achievements" row (it feeds the trophy case, not a game card).

Open Questions

  • Cross-device merge is last-write-wins on the whole blob (platform default). A union-merge of unlocked sets would be strictly better; acceptable v1 because unlocks re-derive from progress on the next play. Revisit if kids report lost trophies.
