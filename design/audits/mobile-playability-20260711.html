platformer
screenshot		 FAIL On-screen move/jump controls (◀ ▶ JUMP) are hidden by Tailwind 'md:hidden' (display:none at >=768px) at the 844px landscape width the game forces via its rotate warning; and in portrait the Level buttons never start gameplay - so there is no touch control to move left/right or jump.
evidence

Coarse pointer confirmed. Game shows a 'Rotate Your Phone' warning in portrait. Re-emulated landscape (844x390) + reloaded: warning clears and tapping 'Level 1' DOES start the game (pause button appears, canvas grows to 812x457). But the on-screen ◀ ▶ JUMP controls have a parent div classed 'md:hidden fixed bottom-4 ...'; getComputedStyle(parent).display === 'none' at 844px width because Tailwind md:hidden hides at >=768px, and a landscape phone is 844px wide. So the only touch controls are display:none (buttons report 0x0). Tapping canvas move/jump zones did nothing (no canvas touch handler). In portrait (390px, where the controls would render) tapping a Level never launches the game (canvas stays at the 358x201 preview, no pause button). Net: no reachable way to move or jump by touch in either posture.

Notes: Root cause is a responsive-breakpoint bug: the mobile control bar is gated on 'md:hidden' which assumes phones are always <768px, but landscape phones (and the game's own forced-landscape posture) exceed that. Fix: gate the controls on useCoarsePointer() instead of a width breakpoint, and/or make portrait Level taps start the game. Instruction copy itself is already touch-correct ('Tap ◀ ▶ to move / Tap JUMP').

Console: 3x 'Unable to preventDefault inside passive event listener invocation' (non-fatal touch-listener noise)

✔ PASS after fix: Mobile controls gated on useCoarsePointer() instead of md:hidden, so they render at the game's own forced-landscape width; passive-preventDefault removed (touchAction: none). Re-audit at 844x390 coarse-pointer: all controls visible (80px arrows, 96px JUMP), moved and jumped by touch, 0 console errors. after-fix screenshot

evidence

Audited by the main auditor under 390x844 touch emulation + iPhone UA override. Tapped SNES console card -> catalog opened (150 games). Tapped 'Donkey Kong 1 - Country' -> emulator iframe loaded EmulatorJS from CDN, but the ROM fetch died: /api/roms/snes/donkey_kong_1_country.smc -> 404 (4x). Direct probe: the upstream cdn-hankshits.up.railway.app answers 302 to a signed storage.railway.app URL (which serves the 4MB ROM with 200), but the proxy route uses redirect:'manual' and treats the 302 as not-ok -> 404. Secondary: EJS_emulator.isMobile is UA-based (true with iPhone UA, so the virtual gamepad path exists on real phones), but window.EJS_VirtualGamepadSettings is set to an invalid options OBJECT ({enabled, opacity, size...}) where EmulatorJS documents an ARRAY of button/zone/dpad definitions (emulatorjs.org/docs4devs/virtual-gamepad-settings). Virtual gamepad behavior must be re-verified after the ROM fix.

Notes: Root cause is a security-hardening regression: the ROM proxy's SSRF guard (redirect:'manual') predates the CDN switching to signed-URL redirects. Fix: validate the Location (https + storage.railway.app) and follow exactly one hop. Then re-verify the virtual gamepad and fix EJS_VirtualGamepadSettings to a valid value.

Console: 4x 'Failed to load resource: 404' on /api/roms/snes/donkey_kong_1_country.smc

✔ PASS after fix: ROM proxy now follows exactly one validated redirect hop to storage.railway.app (was: SSRF-hardened redirect:'manual' turned the CDN's signed-URL 302s into 404s for every ROM, killing the emulator for all users). Bogus EJS_VirtualGamepadSettings object removed (EmulatorJS wants an array; defaults now render). Dev ROM fallback fixed to /api/roms; duplicate Final Fantasy 3 entry removed.
