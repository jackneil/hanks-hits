Live notifications delivery

Branch: feat/live-notifications. Baseline: e5c7ba5. Existing drafts 85, 68 and 42 and all older worktrees/stash are preserved; they are incomplete and cannot be safely merged as preparation for this independent feature.

Acceptance

  • An open page discovers a newer deployed release by WebSocket reconnect and a visible-page version fallback. Refresh and Later wait for safe game breaks; refresh refuses when current saves are not durable.
  • One authenticated connection per page receives invalidations. Persistent notifications reload from an authenticated HTTP endpoint after reconnect, with owner isolation and unread/read controls.
  • Public leaderboard improvements generate crossed-score alerts and top-ten/first-place milestones. Opted-out profiles generate no public alerts. Repeated equal/lower scores and ties do not produce false overtakes.
  • Notification history is bounded to 100 per user. Crossed-score alerts cover the visible top-100 board, rather than unbounded fan-out.
  • No new service. PostgreSQL LISTEN/NOTIFY coordinates gateway replicas; dropped messages are recovered by reading durable history. After every database-listener recovery, invalidate connected private inboxes; reconcile visible-page history periodically so healthy sockets cannot hide a missed database event. Sessions use short-lived signed tickets, strict origins, bounded connections and payloads.
  • Deployment, network loss, hidden tabs, owner changes and shutdown release timers, sockets, listener connections and child processes.
  • Required lint, types, real-Postgres behavior, full tests, build, browser journeys and production read-only checks pass before claiming delivery.

Implementation

  1. Add an additive notifications migration and transactional leaderboard triggers with a per-game/score-type advisory lock before writes and rank reads, schema and private HTTP history/read/ticket APIs.
  2. Add a small WebSocket gateway in front of the existing standalone Next server, bundled at build time. Reuse AUTH_SECRET and DATABASE_URL. Release identity is baked into both browser and gateway.
  3. Add notification context, bell/inbox page, safe release card, and reconnect/version fallback. Reuse existing game-break and durable-save signals.
  4. Review security, scale and UX, run required local CI, publish the reviewed PR, apply the additive migration before merge starts auto-deployment, merge, verify deployment and production, then stop owned processes.

Scope

Release prompts, score/rank notifications and inbox. Multiplayer, presence, challenge tracking, browser push and marketing announcements require their own product contracts.
