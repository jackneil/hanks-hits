Client review blockers:
1. Virtual slots never hydrate, yet READY requires valid hydration for all 32 slots. Define virtual slots as resolved no-op baselines or specify inventoried eager construction.
2. The plan returns a vanilla StoreApi, while live stores and consumers require callable UseBoundStore hooks. Define a compatible hybrid or useStore adapters and inventory all affected consumers.
3. The argumentless useAuthSync contract and Home owner access lack compatibility and subscription semantics. Define the adapter, return-field/state mapping, subscribed owner hook, and teardown/transfer behavior.
4. Hill Climb requires a persisted idempotent lastModified but the live getter reads Date.now, setProgress omits the field, and partialize excludes it. Add state/default/partializer/migration coverage or remove the field from A1.
5. Known historical records are not covered: Checkers already persists version 2 and Oregon has a pre-envelope version-1 record without sync. Define explicit per-entry decoding/migration cases.
6. Marker-loss recovery resets to 1/1 but cannot recover an existing higher server authority. Add an authenticated current-authority recovery handshake.
7. Purge ordering contradicts itself by deleting the ledger before enumerating dynamic payloads. Keep one payloads, ledger, staging, sign-out sequence.
8. The GET lock oracle requires an app lock but the transaction algorithm omits GET. Require GET user lock, authority check, app lock, then same-transaction read and no DML.
9. Direct persisted mutations such as Breakout Game.tsx direct useBreakoutStore.setState are absent from provenance. Add a direct-api-setState binding or refactor to a named generated action.
10. The plan types persist.getOptions as full PersistOptions, but installed Zustand 5 returns Partial<PersistOptions>. Use the installed partial contract with narrowing or a materializing facade.
11. Required integration oracles are string tokens and can pass without executing behavior. Replace them with independent executable setup/assert/evidence contracts.
12. home-owner-snapshot is named in prose but not registered in PROOF_CASES/closure. Register it or use the existing literal proof ID consistently.
