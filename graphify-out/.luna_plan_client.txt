## Smallest state machine

Use the existing `initialSyncDoneRef` as the readiness state:

- `PENDING`: ownership guard, hydration, and initial server reconciliation are incomplete. Autosave, force saves, and beacons are blocked.
- `READY`: set only after the relevant initial-sync branch completes, including merged-state adoption. Normal save paths are enabled.
- `PURGING`: represented by existing `foreignDataRef` plus module-level `foreignPurgePending`. All uploads remain blocked across remounts.

Do not use `syncStatus` as the readiness guard. It is set to `"syncing"` before the ownership check at [`useAuthSync.ts:218-221`](/Users/jack.neil/Github/hanks-hits/apps/web/src/shared/hooks/useAuthSync.ts:218).

Add:

- `forceSyncPendingRef`: latches authenticated `forceSync()` calls received while `initialSyncDoneRef.current` is false.
- `saveInFlightRef`: one active POST at a time.
- `queuedSaveRef`: latest payload requested while a POST is active.

`forceSync()` should latch while pending, then drain after `initialSyncDoneRef.current = true`, reading `getStateRef.current()` at drain time. Clear the latch when entering foreign purge.
